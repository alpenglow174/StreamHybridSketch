\begin{abstract}
Federated linear sketches with secure aggregation and differential privacy (DP) let a server estimate item
frequencies without seeing raw events, but existing methods analyse a fixed dataset in a few rounds. We build an
end-to-end streaming pipeline---Kafka ingestion, eight Flower edge clients with pairwise-mask secure aggregation and
distributed Gaussian noise, a Flower server, and a Grafana dashboard---and reproduce three base methods in it:
DP-HybridSketch, TrieHH and IBLT-based heavy-hitter recovery. On top of the per-window DP-HybridSketch baseline we add
tree-based continual release, a \emph{peeling} estimator, adaptive sketch width, a drift detector and an IBLT layer.
On Gowalla, Sentiment140 and a drifting synthetic stream, the drift-aware variant recovers heavy-hitter F1 after an
abrupt drift in 1.5 instead of 5.5 rounds and cuts upload by 31--61\% at equal privacy; tree release with peeling halves
the cumulative error at a small budget ($\eps=0.125$). We also report where the enhancements do \emph{not} help: tree
release loses on sliding windows and at $\eps\ge1$, and the IBLT costs 2--4$\times$ more communication than a
dictionary-assisted CountSketch.
\end{abstract}

\section{Introduction}
Trending words, busy places and common error codes are \emph{live} statistics over data that should not be
centralised. Federated analytics keeps data local and sends only summaries; \emph{linear} sketches such as
CountSketch~\cite{charikar2002} fit well because a server can add them under secure aggregation (SecAgg) and learn
only the sum~\cite{wu2023,bonawitz2017}. Real data, however, is an unbounded, drifting stream, and every release
spends privacy. Existing federated sketch methods analyse a fixed population in a few rounds~\cite{wu2023,zhu2020,gascon2023}.

\textbf{Problem.} Estimate frequencies and top-$k$ heavy hitters over distributed, drifting streams with federated
sketches, SecAgg and DP, keeping error, upload and cumulative privacy loss low. This needs a release every window, so a
batch job cannot do it, and no single tool covers ingestion, federated orchestration, aggregation, accounting and monitoring.

\textbf{Contributions.} (1)~A streaming pipeline with real data flowing Kafka $\rightarrow$ Flower edges $\rightarrow$
SecAgg $\rightarrow$ server $\rightarrow$ Kafka $\rightarrow$ InfluxDB/Grafana, plus an offline harness running the
identical protocol code. (2)~Reproductions of three base papers. (3)~StreamHybridSketch: five ablated stream extensions.
(4)~A quantitative comparison including negative results.

\section{Related Work and Gap}
\textbf{Wu et al.~\cite{wu2023} (baseline).} \emph{Question:} how to size and reuse a CountSketch under secure
summation, with and without DP. \emph{Data:} Gowalla, C4, Sentiment140. \emph{Metrics:} $\ell_\infty$ error,
communication, $(\eps,\delta)$. \emph{Findings:} the needed width depends on the distribution's tail, and a two-phase
rule finds it; HybridSketch (shared bucket hash, fresh sign hash per round) beats Shared and Fresh sketches; its DP
version is near-optimal. \emph{Model:} none.

\textbf{Zhu et al.~\cite{zhu2020} (TrieHH).} \emph{Question:} can heavy hitters be found from on-device data with
central DP? \emph{Data:} Sentiment140. \emph{Metrics:} precision/recall vs.\ $\eps$. \emph{Findings:} sampling
$\gamma\sqrt n$ users per round and keeping trie prefixes with $\ge\theta$ votes is DP without added noise.
\emph{Model:} none.

\textbf{Gasc\'on et al.~\cite{gascon2023}.} \emph{Question:} what does multi-round heavy-hitter recovery cost when
clients may only send linear sketches? \emph{Data:} Stack Overflow. \emph{Metrics:} F1 vs.\ communication.
\emph{Findings:} IBLTs~\cite{goodrich2011} with threshold sampling need $\sim$10$\times$ less communication than
CountSketch. \emph{Model:} none.

\textbf{Gap.} All three release a fixed number of times. A stream releases every window, so noise or privacy loss
accumulates, the right width changes, and windows must react to drift. The tree mechanism~\cite{dwork2010,chan2011}
handles the first issue for counters but, as we show, conflicts with HybridSketch's fresh signs.

\section{System Architecture}
Fig.~\ref{fig:arch} shows the pipeline. A \textbf{producer} replays a dataset in event-time order into Kafka, one
partition per edge, and marks each window's end with a watermark. Each of 8 \textbf{edges} is a Flower client reading
only its partition: it samples one item per local user, builds each variant's sketch plus its noise share, masks the
payload with pairwise X25519-derived masks and returns it. The \textbf{Flower server} plans each round (widths, seeds,
noise, IBLT threshold), sums the masked payloads (masks cancel), decodes, and publishes top-$k$ releases to Kafka. An
\textbf{evaluator}, outside the protocol, scores releases against exact truth and writes metrics to \textbf{InfluxDB}
for \textbf{Grafana}.

\section{Proposed Enhancement: StreamHybridSketch}
\textbf{Privacy model.} Each user contributes one item per window, so a depth-$d$ CountSketch has $L_2$ sensitivity
$\sqrt d$; the unit is one user in one window (event-level DP~\cite{dwork2010}). Each of $K$ edges adds
$\mathcal N(0,\sigma^2/K)$, so the server never sees un-noised data. Budgets are tracked with a R\'enyi-DP~\cite{mironov2017} accountant.

\textbf{(a) Tree continual release.} Summing $t$ noisy per-window sketches gives noise variance $t\sigma^2$. We instead
release the nodes of a binary tree over windows, so any prefix or window is a sum of $O(\log t)$ nodes; each unit appears
in $\lceil\log_2 T\rceil{+}1$ releases. Upload roughly doubles.

\textbf{(b) Peeling.} Tree nodes must share sign hashes to be summable, which turns HybridSketch into a SharedSketch whose
error is dominated by heavy items colliding across rounds. Per node we estimate the top-200 items, subtract them, read every
item from the residual and add its own estimate back. This is post-processing, so it is free in privacy.

\textbf{(c) Adaptive width.} The server fits a power law to the previous release's top-20 estimates and applies the
two-phase width rule of~\cite{wu2023} (power-of-two widths, smoothed over three rounds), at no extra round or privacy cost.

\textbf{(d) Drift detection.} If the top-50 overlap between the newest window and the sliding window falls below half its
recent mean, the server restarts the window and resets the width.

\textbf{(e) IBLT layer.} Users threshold-sample their item into an additive IBLT, which the server decodes to list heavy
items without a dictionary. It is protected by SecAgg and sampling, not DP.

Algorithm~\ref{alg:round} summarises a round; the baseline is the case with one leaf node, fixed $W$ and fresh signs.
\begin{algorithm}[t]
\caption{One StreamHybridSketch round (window $t$)}\label{alg:round}
\begin{algorithmic}[1]
\Statex \textbf{Server:} plan $\mathcal P_t$: nodes $\mathcal N_t$ completed at $t$ (tree) or $\{(0,t)\}$; width $W_t$; seeds; $\sigma$; IBLT threshold
\For{each edge $e$ \textbf{in parallel}}
  \State consume partition $e$ until watermark $t$; sample one item per user
  \For{each node $(\ell,j)\in\mathcal N_t$}
     \State $S_e^{(\ell,j)}\gets$ CountSketch of local items in rounds $[j2^\ell,(j{+}1)2^\ell)$, width $W^{(\ell,j)}$
     \State $S_e^{(\ell,j)}\gets S_e^{(\ell,j)} + \mathcal N(0,\sigma^2/K)$ \Comment{noise share}
  \EndFor
  \State optional: threshold-sample items, encode IBLT $B_e$
  \State send $\mathrm{mask}_e([S_e,B_e])$ \Comment{$\sum_e \mathrm{mask}_e(x_e)=\sum_e x_e \bmod 2^{64}$}
\EndFor
\State \textbf{Server:} $S\gets\sum_e$ payloads; store nodes; peel IBLT
\State estimate window / cumulative frequencies from the dyadic cover (with peeling); release top-$k$ to Kafka
\State drift test (top-$k$ Jaccard) $\Rightarrow$ reset window; two-phase fit $\Rightarrow W_{t+1}$; IBLT load $\Rightarrow$ threshold
\end{algorithmic}
\end{algorithm}

From the ablations we recommend two configurations: \textbf{SHS-W} (per-round release + (c) + (d)) for window and
current-trend queries, and \textbf{SHS-C} (tree + peeling + (d), fixed width) for long-horizon totals at small $\eps$.

\section{Implementation}
\textbf{Data.} \emph{Gowalla}: 6.1M check-ins in 2010 mapped to 5\,km grid cells (as in~\cite{wu2023}), 295 daily windows,
$\sim$8.5k users each. \emph{Sentiment140}: 1.6M tweets as 22M word events, 124 six-hour windows, $\sim$9.8k users each.
\emph{Synthetic}: Zipf(1.1) over 100k items, 20k users per round, 200 rounds, with the top-200 items replaced at rounds 70 and 140.
It stands in for the multi-GB Stack Overflow data of~\cite{gascon2023}.

\textbf{Tools.} Kafka 3.7.0, Flower~\cite{beutel2020} 1.11.1, Python 3.11, \texttt{cryptography} 42, dp-accounting 0.4.4,
InfluxDB 1.8, Grafana 10.4, in Docker Compose. \textbf{Settings.} Depth 5, baseline width 2048, 8 edges, top-50,
7-round window, $\delta=10^{-6}$; the candidate dictionary is items seen $\ge3$ times. Unit tests check mask cancellation,
IBLT linearity and exact tree sums.

\section{Experimental Setup and Results}\label{sec:res}
\textbf{Metrics.} \emph{Accuracy}: top-50 F1 against three truths---the 7-window sliding window (F1$_w$), the current window
(F1$_n$, which shows drift tracking) and the whole stream so far (F1$_c$)---and the $\ell_\infty$ error of the estimated counts.
\emph{Communication}: upload per edge per round. \emph{Privacy}: $(\eps,\delta)$ per unit from the accountant. \emph{Drift}:
rounds until F1$_n$ regains 90\% of its pre-drift level. \emph{System}: round latency and SecAgg cost. Each variant runs on
the same stream with the same seeds, so differences come from the method alone.

\textbf{Overall (Table~\ref{tab:main}, $\eps=1$).} SHS-W matches the baseline's window F1 on Gowalla (0.79 vs.\ 0.80) with 31\%
less upload, and uses 2.6$\times$ less on the synthetic stream for 0.06 lower F1. On Sentiment140 it loses 0.13 F1 because the
detector fires on organic topic shifts. SHS-C matches the baseline on cumulative F1. Enabling every component at once is worse
than either configuration, and removing peeling raises cumulative error 1.6--3.5$\times$.

\textbf{Privacy over time (Table~\ref{tab:eps}, Figs.~\ref{fig:eps}, \ref{fig:cumtime}).} At $\eps=0.125$ the tree with peeling
cuts final cumulative error 2.0--2.6$\times$ and lifts Gowalla's cumulative F1 from 0.74 to 0.90. The gain shrinks to
1.0--1.3$\times$ at $\eps=0.25$, and from $\eps\ge0.5$ the baseline wins because noise no longer dominates. For short windows
the baseline always wins.

\textbf{Drift (Table~\ref{tab:drift}, Fig.~\ref{fig:drift}).} The detector fires exactly at rounds 70 and 140. The baseline
drops to F1 0.15 and needs 5.5 rounds to recover; SHS-W and SHS-C recover in 1.5, lifting post-drift F1 from 0.56 to 0.85.

\textbf{Communication (Fig.~\ref{fig:comm}).} Adaptive width sits on the fixed-width frontier: it finds a good width without
tuning, but does not beat the best one chosen in hindsight. Without DP, the IBLT needs 2--4$\times$ more upload than a
dictionary-assisted CountSketch on real data; its benefit is needing no dictionary.

\subsection{Live pipeline and system cost}
Table~\ref{tab:system} and Fig.~\ref{fig:grafana} come from a 200-round live run with four variants. With replay paced at
2\,s per window, median round latency is 2.14\,s, mostly waiting for the watermark (1.56\,s); payload building takes 12\,ms and
SecAgg unmasking 1.6\,ms. Replaying the same configuration offline gives identical widths and payload sizes every round
and F1 within 0.04.

\section{Discussion}
\textbf{Meaning.} No single configuration wins everywhere: window and drift queries favour SHS-W, while long-horizon
totals at tight budgets favour the tree, but only with peeling.

\textbf{Negative results.} The tree loses at $\eps\ge1$ and on windows; combining all components hurts; the IBLT costs more
than a dictionary-assisted sketch; FreshSketch beat HybridSketch; the detector raises false alarms on Sentiment140.

\textbf{Limitations.} SecAgg has no dropout recovery; noise seeds are fixed for reproducibility; guarantees are
event-level, not user-level; the IBLT is not DP; edges are cross-silo aggregators; streaming results use one seed per setting.

\section{Conclusion and Future Work}
We built a federated, privacy-preserving streaming heavy-hitter pipeline on Kafka, Flower, SecAgg and Grafana, reproduced
three base papers in it and extended them for streams. The drift-aware variant recovers 3.7$\times$ faster and saves up to
61\% upload; tree release with peeling halves cumulative error at small budgets. Future work: dropout-robust SecAgg,
user-level accounting and DP candidate discovery without a dictionary.
